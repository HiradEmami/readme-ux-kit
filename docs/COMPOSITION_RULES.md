# Composition Rules

Build READMEs from one template, one theme, and a focused component stack.

## Rules

- Lead with what the project does and how to run it.
- Use one hero/header asset at most.
- Use one divider family throughout a README.
- Keep badges factual and short.
- Prefer tables for compatibility, status, config, support, and commands.
- Put trust, support, and security sections near the end unless they are the main product surface.
- Avoid mixing high-motion assets with dense operational docs.

## Anti-Clutter Checks

- More than two animated assets above the first command is usually too much.
- A badge row should not replace a quick start.
- A visual section should not hide missing docs, tests, or support rules.
