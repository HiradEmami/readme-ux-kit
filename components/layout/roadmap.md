# Roadmap

> Maturity: `draft`

Roadmaps show direction without promising more than the project can deliver. A good README roadmap makes status clear, separates committed work from ideas, and gives contributors a useful place to engage.

Use roadmaps for active open-source projects, product libraries, research systems, CLI tools, and template repositories.

## Milestone Roadmap

```markdown
## Roadmap

| Milestone | Status | Focus |
| --- | --- | --- |
| v0.1 | Complete | Core templates, badge components, and asset previews |
| v0.2 | In progress | Layout components, interactive sections, and status blocks |
| v0.3 | Planned | Theme packs, richer examples, and contribution docs |
| v1.0 | Planned | Stable component API, full preview catalog, release guide |
```

## Now Next Later

```markdown
## Roadmap

### Now

- Complete reusable README component docs.
- Verify asset references across examples.
- Improve preview pages for easier copy/paste.

### Next

- Add full project templates for libraries, services, ML projects, and portfolios.
- Add theme bundles that combine banners, badges, dividers, and layouts.
- Add contribution guidance for new assets and components.

### Later

- Publish a searchable component catalog.
- Add screenshot-based visual regression checks for generated previews.
- Provide package-based installation for reusable assets.
```

## Contributor-Friendly Roadmap

```markdown
## Roadmap

| Track | Good first contribution | Larger contribution |
| --- | --- | --- |
| Components | Improve copy, examples, or compatibility notes | Add a full README section pattern |
| Assets | Add alt text guidance or preview metadata | Add a themed visual asset set |
| Templates | Tighten setup instructions | Create a new project template |
| Tooling | Improve generator help text | Add validation for asset references |
```

## Roadmap Language

```text
Committed: "In progress", "Scheduled", "Targeted for v0.3"
Flexible:  "Planned", "Exploring", "Candidate"
Blocked:   "Blocked by", "Waiting on", "Needs design"
Avoid:     "Coming soon", "Guaranteed", "Almost done" when dates are uncertain
```

## Design Rules

- Separate active work from ideas.
- Use statuses consistently: `Complete`, `In progress`, `Planned`, `Exploring`, `Blocked`.
- Keep dates out unless they are realistic and maintained.
- Link roadmap items to issues or discussions when contributors can help.
- Do not let the roadmap replace a changelog. Roadmaps show future direction; changelogs record shipped work.

## Copy Checklist

- Remove stale milestones before publishing.
- Link important items to issues, discussions, or project boards.
- Keep the current milestone near the top.
- Mark experimental work honestly.
